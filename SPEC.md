# Product specification

## 1. Product definition

### Problem

Desktop and Downloads collect screenshots, installers, archives, documents, exports, project files, and ambiguously named downloads. Manual cleanup requires repeatedly opening files, understanding them, creating folders, renaming them, and remembering whether an item can be discarded.

### Product promise

The app turns a cluttered folder into a reviewable organization plan. It never mutates files during analysis, never deletes automatically, and makes every applied session reversible.

### Target user

Individual Mac users, especially developers and knowledge workers, who accumulate many downloads and desktop files and want assistance without surrendering control of their filesystem.

### Relationship to Yoink

Yoink already provides a mature temporary drag-and-drop shelf across apps, windows, Spaces, and full-screen apps. This app complements it and does not reproduce that interaction. Optional future interoperability may expose a Finder Quick Action or share action, but Yoink integration is not part of version 1.

## 2. Goals

- Scan Desktop, Downloads, and multiple user-selected folders.
- Explain accumulated files through deterministic local categories.
- Suggest a structured destination inside a visible review area.
- Suggest safe, useful filenames without changing file extensions.
- Allow batch approval and individual correction.
- Apply filesystem changes transactionally and provide session-level undo.
- Offer optional OpenAI assistance with explicit privacy controls.
- Make repeated accepted choices convertible into deterministic user rules.

## 3. Non-goals for version 1

- Drag-and-drop shelf or clipboard manager.
- General disk cleanup, cache deletion, malware scanning, or app uninstallation.
- Automatic deletion or irreversible cleanup.
- Cloud sync, multi-user collaboration, or team policies.
- Background AI calls without a visible user action.
- Arbitrary scripts or shell commands generated by AI.
- Full semantic indexing of the user's filesystem.

## 4. Main workflow

### 4.1 Onboarding

The app explains the safety model before asking for access. The user grants access to Desktop, Downloads, or any custom folder through a system folder picker. Security-scoped bookmarks are stored for later access.

The user chooses a central review root. Default suggestion:

```text
~/Tidy Review/
```

The name and location are configurable.

### 4.2 Scan

Scanning is read-only. The app records metadata and calculates local signals:

- original URL and relative path
- filename, extension, Uniform Type Identifier, size, creation and modification dates
- download age
- package, alias, symlink, hidden-file, and directory status
- content hash only when required for duplicate detection
- deterministic category and reason
- whether the item matches an exclusion or sensitive-file rule

The app must not recursively scan large trees by default. A custom folder has a configurable depth, defaulting to its direct children.

### 4.3 Plan

The app proposes a session folder:

```text
~/Tidy Review/2026-07-12 14-30/
├── Documents/
├── Screenshots/
├── Images/
├── Installers/
├── Archives/
├── Project Files/
├── Sensitive/
└── Unclear/
```

Each item contains:

- original name and location
- proposed name and relative destination
- deterministic or AI origin
- confidence: high, medium, or low
- concise reason
- warnings and collision status
- approval state

Planning never creates, renames, moves, or deletes source files.

### 4.4 Review

The main window uses three functional regions:

- Source sidebar: Desktop, Downloads, custom folders, and previous sessions.
- Plan list: grouped, sortable, searchable file proposals with batch selection.
- Inspector: Quick Look, original/proposed names, destination, reason, privacy state, and editable fields.

Primary actions:

- Approve selected
- Reject selected
- Edit category, filename, or destination
- Stage approved files
- Exclude this item or matching items in the future

Low-confidence and sensitive items are never batch-approved by default.

### 4.5 Stage and commit

“Stage approved files” performs a preflight and then applies one transaction:

1. Revalidate that every source still exists and matches the scanned identity.
2. Resolve filename collisions without overwriting.
3. Create the session folder and category folders.
4. Move or copy each approved item according to the configured operation.
5. Write an append-only transaction record after every successful step.
6. Stop safely on an unexpected error and offer rollback of completed steps.

The default operation is move. The setting can be changed to copy. Existing destination files are never overwritten.

### 4.6 Finalize or undo

A staged session remains visible in the app. The user can:

- reveal the session in Finder
- move individual items to final destinations
- keep the organized session folder as the final result
- undo the complete session

Undo restores original names and locations where possible. If an original path is now occupied, the app asks for resolution and never overwrites the occupant.

## 5. Classification

### Initial deterministic categories

- Documents
- Screenshots
- Images
- Video
- Audio
- Installers and disk images
- Archives
- Code and project files
- Fonts
- Sensitive files
- Duplicates
- Unclear

Classification rules must be inspectable and testable. Extension alone is not always sufficient; Uniform Type Identifier and package status take precedence.

### Sensitive-file defaults

At minimum, treat the following as sensitive or excluded from AI:

```text
.env, .pem, .key, .p8, .p12, .mobileprovision,
credentials.*, id_rsa*, id_ed25519*, *.sqlite, *.db
```

Users can add names, extensions, glob-like patterns, and folders to an exclusion list.

## 6. Rename suggestions

### Invariants

- Never change or remove the real extension.
- Remove illegal path separators and control characters.
- Normalize whitespace without destroying meaningful punctuation.
- Preserve dates, invoice numbers, project codes, and version numbers when confident.
- Never overwrite an existing file.
- Limit filename length conservatively.
- Show exact before/after values.
- Low-confidence suggestions require individual approval.

### Local suggestions

Version 1 should support deterministic cleanup such as repeated download suffixes, excessive whitespace, known screenshot prefixes, and consistent date formatting without requiring AI.

### AI suggestions

AI may suggest a concise descriptive basename, category, relative destination, confidence, and reason. It may not control absolute paths, extensions, commands, deletion, or approval.

## 7. OpenAI functionality

### User-owned key

The user enters an OpenAI API key in Settings. Store it only in macOS Keychain. Provide Test Connection and Delete Key actions. Never include a shared application key in the client.

### API design

- Use the OpenAI Responses API.
- Use Structured Outputs with a strict JSON Schema for organization proposals.
- Treat every response as untrusted input and validate all values locally.
- Make requests stateless unless a future reviewed feature needs continuity.
- Implement cancellation, timeout, retry with backoff, and understandable errors.
- Keep the model configurable behind an internal capability abstraction rather than scattering model identifiers through UI code.

### Privacy levels

The user chooses an explicit maximum. Version 1.0 ships the first two tested levels; the content-bearing levels remain visible roadmap capabilities but unavailable until their separate consent and extraction safeguards are implemented:

1. Off: no AI requests.
2. Metadata only: filename, extension, type, size range, and dates.
3. Text preview (post-1.0 gated capability): limited extracted text for individually eligible files.
4. Visual preview (post-1.0 gated capability): a reduced image or OCR for individually eligible images and PDFs.

The batch review must show which files would transmit which data before the request begins. Sensitive files remain excluded regardless of the batch setting unless a future feature introduces deliberate per-file override.

### Cost and failure behavior

Show the number of items in an AI batch and an approximate usage indication. A failed or unavailable AI call must not block deterministic scanning or manual organization.

## 8. Rules and learning

The app does not silently “learn” opaque behavior. After the user accepts or edits a proposal, it may offer to create an explicit rule, such as:

```text
When filename starts with "Screenshot" and image dimensions are present,
place it in Screenshots and use YYYY-MM-DD – <title>.
```

Rules are ordered, enabled/disabled, editable, exportable, and locally evaluated. Conflicting rules show a warning.

## 9. Settings

- General: app language (system default, English, or German), launch at login, menu bar presence, notifications.
- Sources: watched folders, scan depth, age threshold, exclusions.
- Review: review root, move/copy default, session retention.
- Renaming: naming style, date style, collision suffix style.
- AI: API key, connection test, privacy level, quality preference.
- Rules: ordered deterministic rules.
- Updates: manual checks against the signed public stable feed and opt-in automatic checks.
- Help: open the localized offline guide and interactive workflow tour.
- Changelog: show the installed version and build plus categorized, localized release notes from the bundled version history.

The main-window status bar displays the installed version, build number, and latest release summary. Activating it opens Settings directly on the Changelog tab.

## 10. Help and guided learning

- Provide a searchable offline Help window in every supported interface language.
- Make Help available from onboarding, the review toolbar, Settings, menu bar, and the standard macOS Help menu with Command-?.
- Cover setup, plan review, staging and undo, safety and privacy, optional AI assistance, rules, exclusions, shortcuts, and troubleshooting.
- The interactive tour must be a pure in-memory simulation. It may not request folder access, scan, create, rename, copy, move, delete, transmit, or persist user files or data.
- Help content follows the selected app language immediately and uses the same extensible resource-bundle architecture as the rest of the interface.

## 11. Menu bar behavior

The menu bar is a lightweight entry point, not the complete application. It displays pending file count, starts a scan, opens the current plan, and shows the most recent session. All consequential review happens in the main window.

## 12. Accessibility and native behavior

- Complete keyboard navigation and VoiceOver labels.
- System text styles, reduced-motion support, and sufficient contrast.
- Quick Look for supported files.
- Dragging from the staged result to Finder is allowed.
- Respect light, dark, and increased-contrast appearances.
- Destructive-looking actions require clear labels even if technically reversible.

## 13. Data and privacy

- Local data includes bookmarks, settings, rules, scan cache, proposals, and transaction logs.
- Do not store file contents in the app database.
- Extracted previews are ephemeral unless the user explicitly saves them.
- Redact filenames and paths from diagnostic logs by default.
- Provide “Delete all app data” without deleting user files.

## 14. Acceptance criteria for version 1.0

- At least Desktop, Downloads, and custom sources can be granted and rescanned.
- Scanning is demonstrably read-only.
- Deterministic classification works without an API key.
- Proposals can be edited and partially approved.
- Approved files can be staged without overwriting any file.
- A complete session can be undone after app restart.
- Interrupted transactions recover coherently.
- Sensitive files are excluded from AI by default.
- API keys are Keychain-backed and absent from logs and repository contents.
- AI output is schema-validated and path-sanitized.
- Full test suite, signed build, notarized release, Sparkle update, and launch verification are documented and repeatable.
